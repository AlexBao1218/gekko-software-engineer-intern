# Q1 审批特殊情况核验（2026-10-13）

## 结论与适用范围

**题目 Q1 的审批规则和本轮补测的事务边界通过；不能称为已经可以用于真实业务的完整审批系统。**
原 Q1 提交为 `6ee40ef`。本轮在其基础上增加 45 项测试，发现并修复重复 JSON 字段被静默覆盖的问题。
完整根目录测试为 **157 passed, 1 warning in 8.07s**；八个并发场景额外重复十轮全部通过。
这是 macOS/Python 3.12.14/SQLite 上的行为证据，不是对所有输入、负载、操作系统或硬件故障的数学保证。

## 1. 完整状态规则

成功为 HTTP 200；所有表内“拒绝请求”均为 HTTP 409，带当前状态和原因，案件及审核历史不变。
业务上的“拒绝申请”本身是一次成功操作，与“拒绝非法请求”不同。

| 当前状态 | 一级通过 | 一级拒绝 | 二级通过 | 二级拒绝 |
|---|---|---|---|---|
| pending（尚未完成 OCR） | 拒绝请求 | 拒绝请求 | 拒绝请求 | 拒绝请求 |
| ocr_failed（OCR 失败） | 拒绝请求 | 拒绝请求 | 拒绝请求 | 拒绝请求 |
| ocr_done（OCR 成功） | stage1_approved | stage1_rejected | 拒绝请求 | 拒绝请求 |
| stage1_approved（一级通过） | 拒绝请求 | 拒绝请求 | stage2_approved | stage2_rejected |
| stage1_rejected（一级拒绝） | 拒绝请求 | 拒绝请求 | 拒绝请求 | 拒绝请求 |
| stage2_approved（二级通过） | 拒绝请求 | 拒绝请求 | 拒绝请求 | 拒绝请求 |
| stage2_rejected（二级拒绝） | 拒绝请求 | 拒绝请求 | 拒绝请求 | 拒绝请求 |
| exported（已导出） | 拒绝请求 | 拒绝请求 | 拒绝请求 | 拒绝请求 |

上述 8×2×2=32 种组合全部经过 HTTP 测试：4 条合法、28 条冲突。
另测真实两级顺序、两级拒绝后的所有后续决定、重复决定和改判。
`exported` 是显式测试前置状态，**尚无真实导出端点**；不能据此声称 Q2 导出排除已验收。

## 2. 输入、标识及错误边界

| 特殊情况 | 结果 | 数据检查 |
|---|---|---|
| 缺少 stage/decision、空请求、JSON null | 422 | 不改状态、不留成功审核记录 |
| 整个请求是数组、数字、字符串 | 422 | 同上 |
| JSON 语法不完整 | 422 | 同上 |
| 无效 UTF-8 请求体 | 400 | 同上 |
| 用 text/plain 发送 JSON 文本 | 422 | 同上 |
| stage 为 0、负数、3 | 422 | 同上 |
| stage 为字符串 "1"、浮点数 1.0、布尔值、null、数组或对象 | 422 | 同上；不会自动转换成整数 |
| decision 为大写 APPROVE、空串、带空格、null、布尔值、数组、对象或含 NUL | 422 | 同上；不会猜测意图 |
| stage 为 NaN/Infinity、decision 或额外字段名含孤立 Unicode surrogate | 安全的 422 | 不再因错误响应序列化而返回 500 |
| 额外传 status，试图直接指定二级通过 | 422 | 无法绕过状态机 |
| 同一 JSON 重复 stage/decision（相同值、相反值、Unicode 转义同名字段） | **422，本轮修复** | 不选择最后一个值，不执行审批 |
| 查询参数传 stage=1，JSON 正文传 stage=2 | 按正文校验；未一级通过则 409 | 查询参数不能覆盖审批正文 |
| 不存在的 UUID、用 case_ref 代替 case_id | 404 | 不会误审其他案件 |
| 案件 ID 含 SQL 注入式文本或 NUL | 404 | 参数绑定，不会扩大 UPDATE 范围 |

422 有两种细节格式：普通模型错误为 `detail` 列表；重复 JSON 字段为
`detail.code=duplicate_json_field`。400 的请求体解码错误由框架返回简要说明。
上述非成功操作均验证没有新增成功审核记录；没有实现记录所有失败请求的安全日志。

## 3. 重复及并发

| 场景 | 实测结果与含义 |
|---|---|
| 同一级连续重复“通过”或“拒绝” | 第一次 200，后续 409；一条记录 |
| 先通过再反悔拒绝，或先拒绝再通过 | 已完成阶段不能改判，409 |
| 同一级两人同时通过 | 一个 200，一个 409；一条记录 |
| 同一级一人通过、一人拒绝 | 先取得事务锁并提交者成功；另一人 409；不预设谁胜出 |
| 同一级 8 个同时通过 | 一个 200，七个 409；两级均测试 |
| 同一级 8 个相反决定竞争 | 一个 200，七个 409；状态与唯一审核记录一致；两级均测试 |
| 一级通过与二级决定同时到达 | 一级先提交时两者可以都 200；二级先读到旧状态时返回 409，重新读取后可重试 |
| 一级拒绝与二级决定同时到达 | 一级拒绝成功；二级一定 409；不能越过拒绝 |
| 不同批次存在相同 case_ref，分别审核 | 以唯一 case_id 隔离；双方可成功，各自的批次统计正确 |
| 两个独立 Uvicorn 进程访问同一 SQLite，同时通过或做相反决定 | 一个 200，一个 409；证明保护来自数据库事务，不只来自单个 Python 进程 |

额外运行命令（十轮，每轮八项、40 次审批，共 80 场景/400 请求）：

```bash
for i in {1..10}; do
  python -m pytest q1_api/tests/test_review_edges.py -q \
    -k 'eight_concurrent or concurrent_different_stages' || break
done
```

这些是有界并发正确性测试，**不是吞吐量、长时间压力或延迟 SLA 验收**。
SQLite 写锁覆盖数据库：不同案件也会竞争锁。锁等待超过限制仍可能 503；不承诺任何负载下都只出现 200/409。

## 4. 故障、恢复及客户端不确定性

| 故障点 | 实测结果 |
|---|---|
| 更新案件状态时触发数据库错误 | 500，隐藏内部错误；原状态、零记录；移除故障后重试成功 |
| 新增审核记录时触发数据库错误 | 500；已经执行的状态变更也回滚 |
| 其他连接持有写锁 | 有界等待后 503 + Retry-After: 1；状态/历史不变；释放锁后成功 |
| 读连接阻止写事务最终 COMMIT | UPDATE 和 INSERT 不能部分生效；提交失败返回 503，两者回滚；释放读锁后重试成功 |
| 已执行状态更新及审核 INSERT、但尚未提交时强制杀进程 | 重新访问 SQLite 后两者回滚；再次审批成功；integrity_check=ok |
| 已提交但调用者尚未知结果时强制杀进程 | 状态与记录保留；重试 409；不会产生第二条记录；integrity_check=ok |
| 完成两级审批后重启真实 API 进程 | 状态和两条审核记录保留，重复二级审批 409 |

两项强制杀进程测试直接调用真实 `Database.review_case`，使用临时连接 trigger
设置精确提交前切点，提交后切点位于方法返回之后。注入仅在测试子进程中，生产代码没有故障开关。
这是进程崩溃演练，**没有模拟断电、磁盘损坏或真实网络丢包**。
响应不确定时应重新查询案件状态；重复请求防止重复写入，但没有 Idempotency-Key 或原响应重放功能。
冲突响应不证明“上一次是当前用户成功提交”，也可能是其他请求先完成。

## 5. 本轮发现与修复

默认 JSON 解析把同名字段折叠成字典最后值，严格 Pydantic 模型看不到被覆盖字段。
原请求 `{"stage":1,"decision":"reject","decision":"approve"}` 会实际通过。
已保存旧提交上的探测，并让六个回归测试先出现 `200 != 422`，再修复。
审核专用依赖使用保留字段对的解码方式检查重复字段，再进入原来的类型/状态/事务规则。
不修改其他端点，不新增依赖，不改变原有四条合法转换。

新增测试中，39 项是对既有实现的加强验证；只有重复字段的六项经过本轮 RED→GREEN。
没有把所有新增测试都宣传成先失败再实现，也没有声称本轮进行了新的独立代理审查。

## 6. 仍不具备的能力

| 边界 | 当前事实 | 与题目的关系 |
|---|---|---|
| 身份、角色与两人分离 | 无登录认证；同一客户端可完成两级；无法限制普通员工/主管，也不能阻止自审 | 非核心 Q1 要求，真实业务上线前必须补齐 |
| 审核人、拒绝理由、安全审计 | 只存 stage/decision/前后状态/UTC 时间；无 actor、业务理由、失败请求审计或防篡改存储 | 基础审计记录已实现，更强审计不在本轮范围 |
| 拒绝后重开、撤回、返回一级、纠错后再审 | 当前均禁止；没有管理入口 | 拒绝终止符合原题；退回是后续面试修改练习 |
| 数据版本与过期页面 | 按事务内最新状态校验，没有页面版本令牌 | 同阶段旧页面会冲突；将来允许资料编辑时须防止批准已变化内容 |
| OCR 和导出并发 | 当前没有对应业务端点 | Q2 必须测试 OCR 不覆盖人工审批、拒绝不导出、审批与导出竞争 |
| 持续高负载与请求体上限 | 本轮有限并发通过；审核路由没有独立请求体体积上限 | Q3 代理限制及必要容量验证待做 |
| 更广环境与存储灾难 | macOS 验证；未做 Linux CI、断电/磁盘满/文件损坏演练 | 不用本轮结果替代 CI、Q3 备份恢复 |
